비교 기준은 화면 교체 직전 `649802a`의 `host/public/m.html`과 목적별 화면이다.

설계상 변경은 회귀와 구분한다. 촬영 직후 자동 전송은 사진 검토 후 명시적 전송으로,
단일 목적 화면은 목적 선택 후 반복 작업으로 바뀌었다. 한 번에 12장 제한은 30장으로
확장했고, Drive 원본은 변환 없이 보관하며 표출/메일/공유용 복사본만 JPEG로 준비한다.
이메일과 공유는 사용자 요청대로 `보관하고 표출`, `보관없이 표출`에만 제공한다.

검증 명령: `cd host; npm run test:camera-ui`는 기존 기본 시나리오와 통신/공유 시나리오를
모두 실행한다. 카메라 API 테스트는 실제 메일 큐와 로컬 테스트 전송을 연결한다.
운영 Google Drive·운영 Gmail 또는 실제 휴대폰의 카카오톡 수신자에게는 보내지 않았다.
네이티브 공유 경계는 파일을 검사하는 테스트 대역으로 확인하므로 실제 기기/카카오톡 전송은 별도 확인 범위다.

보관까지 포함한 전체 취소는 기존과 같이 관리자 설정 `cancelSec` 안에서만 가능하다(기본 60초).
`보관하고 표출`에서 사진을 취소하면 Drive 보관도 취소하며 대기 이메일을 취소한다.
표출 우선 개발에서 별도의 ‘게시만 취소’를 추가했다. 개별/마지막 묶음으로 제공하며 보관과 메일을 유지하고 전체 취소 시간 이후에도 가능하다.
다른 브라우저에서 올린 사진은 해당 기기의 취소 버튼에 나오지 않는다.
이 제약을 취소 기능 자체의 소실과 혼동하지 않도록 동작 범위와 남은 시간을 표시한다.

빠른 표출/원본 전송 분리 후에도 이메일·공유·메일만 취소·전체 취소·문구·이전 저장 키 이관을 검증했다.
추가 검증은 Google 장애 중 선표출, 원본 미접수/위치 미지정 구분, 원본의 바이트 보존,
원본 전송 중 재시작/새 게시 우선권, 게시만 취소 후 보관 유지, 서버 재시작 복구이다.
