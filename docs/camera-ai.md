# AI 사진 꾸미기와 재사용 행사 프레임

기존 촬영 → 꾸미기 → 확인 → 전송 흐름에 AI 탭을 추가한다. AI 버튼을 누를 때만 서버가 Google Gemini를 호출한다. 기본 뽀샤시·색감·프레임·벡터 꾸미기는 API 키가 없거나 AI 연결이 실패해도 계속 사용할 수 있다.

## Railway 설정

- `GEMINI_API_KEY`: Google AI Studio에서 발급한, 이미지 생성 결제가 활성화된 프로젝트의 키. Railway 서버 변수에만 등록한다. 브라우저·Git·로그에 넣지 않는다. 키가 없으면 AI 탭에 연결 준비 중을 표시하고 생성 버튼을 비활성화한다.
- `CAMERA_AI_ENABLED=false`: 새 AI 호출을 중지한다. 저장한 행사 프레임은 계속 제공한다.
- `CAMERA_AI_MODEL`: 기본 `gemini-3.1-flash-image`. 설치한 AI SDK의 Google provider와 공식 이미지 편집 API 문서를 확인해 선정했다. 모델을 바꿀 때 이미지 출력·입력과 `imageConfig.imageSize=1K` 지원을 확인한다.
- `CAMERA_AI_OWNER_DAILY_LIMIT`: 기기별 하루 생성 접수 한도, 기본 8회(최대 100).
- `CAMERA_AI_DAILY_LIMIT`: 서버 전체 하루 생성 접수 한도, 기본 40회(최대 1000). KST 자정에 초기화한다. 카메라 계정 하나를 공유하므로 기기 한도는 쿠키 기준이고 전체 한도가 최종 비용 상한 역할을 한다. 금액 한도는 제공자의 결제 설정도 사용한다.
- 기존 `DATA_DIR` 영구 볼륨이 필요하다. `photo-archive/camera-ai/state.json`에 사용량과 프레임 목록, `frames/`에 장식 JPEG를 보관한다. 키는 이 파일에 보관하지 않는다.

## 사용과 저장

- 배경 정리: 인물·표정·옷·구도를 유지하고 배경의 방해 물건을 정리하도록 요청한다. 수채화·만화는 인물을 알아볼 수 있는 스타일 변환을 요청한다. 생성형 편집이므로 결과의 얼굴·인원·행사 내용을 사용자가 확인한 뒤 적용한다. 얼굴 보정은 기존 기기 내 뽀샤시를 유지한다.
- 사진 편집은 매번 원본을 기준으로 한다. AI 결과를 반복 입력해 화질을 떨어뜨리지 않는다. 기존 색감·프레임·꾸미기는 AI 결과 위에 다시 적용한다. AI 결과를 받으면 뽀샤시 강도는 0으로 되돌아가며 필요하면 다시 적용할 수 있다.
- 사진 전송 안내 체크가 있어야 편집을 호출할 수 있다. 원본의 축소 JPEG만 전송하고 서버가 EXIF 등 메타데이터를 제거한다. 원본 보관 정책은 기존과 같다.
- AI 결과는 기존 사진을 바로 덮어쓰지 않는다. 비교·AI 효과 제거·닫기 후 취소가 가능하다. ‘이 사진으로 계속’을 누를 때만 대기 사진의 편집을 갱신한다. `aiFile`은 JPEG 한 장만 IndexedDB의 `:a` 키에 저장하고, 최종 꾸민 사진은 기존 `beautyFile`에 저장한다. 원본 파일은 그대로 유지한다. 대기 저장 한도에 AI 결과 크기도 포함한다.
- 행사 프레임 생성은 분위기 문장만 전송하며 사진은 보내지 않는다. 생성한 장식은 서버에 최대 24개 보관하고 카메라 사용자들이 공통으로 재사용한다. 프레임 → 행사·날짜 → 보관한 장식에서 선택한다. 같은 장식에 행사명·날짜는 앱이 정확하게 그린다. 장식은 사진 바깥 여백에만 보이며 사진을 자르거나 얼굴을 가리지 않는다. 재사용·이름/날짜 수정에는 AI를 호출하지 않는다.

## 자원과 오류 처리

- 기기에는 추가 AI 모델을 올리지 않는다. 원본 비교·현재 AI 이미지·현재 합성 미리보기만 디코딩한다. 사진 최대 2048px, 서버 입력 최대 1600px, 프레임 장식 최대 1024px. 이전 AI 결과와 프레임 Bitmap은 교체하거나 닫을 때 해제한다.
- 인증·동일 출처 확인은 기존 `/live/api/camera` 미들웨어를 공유한다. 사진 결과는 요청 기기만 읽거나 취소할 수 있다. API 응답은 `private, no-store`이다. 저장한 행사 장식은 인증한 카메라 사용자에게만 제공한다.
- 동시 생성 서버 2개·기기당 1개, 업로드 5MB·디코드 2000만 픽셀 제한. 110초 뒤 provider 호출을 중단한다. 사용량은 접수 전에 영구 저장하고 실패·취소도 횟수에 포함한다. 이미 비용이 발생했을 수 있기 때문이다. SDK 재시도는 0이며 서버 재시작 시 자동으로 재호출하지 않는다.
- 요청 ID가 같으면 기존 작업을 돌려주고 중복 생성하지 않는다. 생성 중 뒤로가기·닫기는 작업 취소를 요청한다. 취소는 이미 사용된 호출 비용의 환불을 보장하지 않는다.
- 원본 입력은 디스크에 저장하지 않는다. 사진 결과는 소유 기기만 접근하는 임시 서버 파일로 최대 약 16분 보관하고 정리한다. 서버 재시작 시 임시 결과를 지운다. 행사 장식과 사용량만 재시작 후 유지한다.
- 키 미설정·한도 초과·실패·취소 시 기존 편집은 유지하며 자동 대체 생성이나 업로드를 하지 않는다.

## 검증

- `node --test tests/camera-ai.test.js`: 인증 전제, 동의·입력 검증, 키 미설정, 사용자 격리, 중복 호출 방지, 영구 한도, 취소, 프레임 재시작/재사용, 설치 SDK의 Gemini HTTP 요청·이미지 응답 검증(가짜 전송).
- `npm run test:camera-ai` (`host/`): 모바일에서 사진 편집·비교·기존 색감 유지·프레임 생성/재사용·저장/재접속·원본 보관·취소/실패·다른 기기 프레임 접근·320px 화면 확인. 가짜 provider를 사용하며 실제 사진을 외부로 보내거나 결제하지 않는다.
- 실제 키 등록 뒤에는 행사 프레임 1회 생성과 테스트 사진 1장으로 실제 결과 품질·응답 시간·과금을 확인한다. 키 없는 배포를 실제 AI 품질 검증 완료로 표현하지 않는다.

공식 근거: https://ai.google.dev/gemini-api/docs/image-generation 및 설치된 `ai/docs/03-ai-sdk-core/35-image-generation.mdx`, `@ai-sdk/google/docs/15-google.mdx`.
