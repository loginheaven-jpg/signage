# 예봄 카메라 간편 촬영 흐름

## 기본 경로

첫 화면은 큰 `촬영하기`와 `사진 선택`이다. 폰 기본 카메라를 사용하며 첫 화면에서 카메라를 계속 켜거나 얼굴 모델을 미리 올리지 않는다. 기본 등록 방식은 화면에 올리기+원본 보관이다. 새 작업 때 목적 선택과 설정 시작 단계를 생략한다.

촬영·선택 → 사진 확인 → 화면에 올리기. 촬영 후 꾸미기를 자동으로 열지 않는다. 사진 확인에서 `사진 꾸미기`를 누른 경우에만 기존 뽀샤시·색감·프레임·꾸미기·AI를 연다. 적용 후 확인 화면으로 돌아오고 최종 등록 버튼을 눌러야 업로드한다.

첫 등록 때 등록자 이름·모니터가 빠졌으면 필요한 정보만 확인하고 기억한다. 그 창을 닫으면 전송하지 않는다. 이름은 입력한 표시 정보이며 인증은 기존 촬영 암호와 기기 소유자 쿠키를 유지한다. 여러 모니터가 있으면 임의로 하나를 고르지 않고 최초 선택을 요구한다. 모니터가 하나인 경우에도 상단에 선택 대상을 표시한다. 오프라인·목록 조회 실패를 연결됨으로 표시하거나 다른 모니터로 바꾸지 않는다.

사진 한 장은 큰 미리보기로 보여준다. 날짜·파일 정보는 펼침 영역, 문구·이메일은 `추가 옵션`으로 옮긴다. 영상 촬영, 보관만 하기, 내 사진은 보조 경로로 제공한다. `더보기`에서 등록 방식·이름·모니터·행사·사진 보내기·내 사진·설치·로그아웃을 연다. 기존 대량 보관·영상·메일·공유·취소 기능은 유지한다.

등록 후 `다음 사진 촬영`을 주 동작으로 제공하고, 공유와 등록 상태는 선택해서 연다. 서버 접수 완료와 실제 모니터 표시 확인은 구분한다. 표시 확인은 플레이어의 응답이 있을 때만 보여준다. 일부 전송 실패는 대기 사진을 남기고 같은 요청으로 재시도한다.

재접속·촬영 화면 이동 시 아직 올리지 않은 사진을 버리지 않는다. 촬영 화면의 `아직 올리지 않은 사진 N장 · 사진 보기` 버튼 전체를 누르면 바로 사진 확인 화면으로 복귀한다. 복원 시 일반 알림에 같은 안내를 중복해서 남기지 않는다. 각 사진 아래의 `삭제`로 한 장씩 정리하며, `전체 삭제`는 확인 후 목록을 비운다. 마지막 사진을 지우면 촬영 화면으로 돌아오고 안내도 즉시 사라진다. 휴대폰 앨범과 이미 등록한 사진은 삭제하지 않는다.

실패 후 고정된 전송 설정은 목적·행사·이메일 변경을 막아 재시도 중 중복 전송을 방지한다. 접수 여부가 불확실한 사진이 포함되면 `등록 확인이 필요한 사진`으로 표시하고, `목록에서 빼기` 또는 `목록 비우기`는 이미 접수된 사진을 취소하지 않는다는 확인을 받는다. 등록 취소는 기존 내 사진에서 한다. 삭제 시 해당 작업의 실패 안내만 정리하고 네트워크·저장 오류 등 별도 알림은 유지한다. 등록한 사진의 원본 전송 대기는 별도로 표시하며, 미등록 목록을 삭제해도 원본 전송 목록을 지우지 않는다. 브라우저 뒤로가기는 선택창 닫기와 이전 화면으로 이동하며, 접수 중에는 기존 이탈 방지를 유지한다.

## 행사 선택

1. 이 폰에서 최근 확정한 개인 행사(`camera.lastTarget`)
2. 개인 선택이 없으면 촬영 연도 아래 `미분류` 폴더

서버가 사진·영상 접수 시 저장 대상을 확정한다. 촬영 연도는 기존 사진 날짜 판독 규칙을 따르며 알 수 없으면 접수 연도(한국 시간)를 사용한다. 연도·미분류 폴더가 없으면 Drive 전송 중 생성한다. Drive 장애 시 원본과 확정 대상을 서버에 유지하고 재시도한다. 같은 이름 폴더가 여러 개면 임의 선택하지 않는다.

자동 보관 위치는 개인 선택으로 기억하지 않는다. 개인이 행사 폴더를 명시적으로 선택하면 그 선택을 우선한다. 대상 폴더 오류를 미분류로 조용히 변경하지 않으며, 이미 접수한 사진은 나중의 설정 변경으로 다른 행사로 옮기지 않는다.

## 관리자 배정

이전 공통 현재 행사 설정은 새 촬영 기본값으로 사용하지 않는다. 관리 화면은 자동 보관 정책을 안내한다. 기존 위치 미지정 사진은 자동 소급 배정하지 않고, 사진 보관함의 관리자 일괄 배정으로 처리한다. [원본 확인·배정·Drive 검증 절차](photo-assignment.md)를 따른다.

## 검증

`npm run test:camera-flow`: 실제 촬영 버튼→폰 파일 선택 경계→선택적 꾸미기→첫 등록 정보→반복 등록, 접수/표시 구분, 개인 행사 우선/촬영 연도 미분류 대체, 재접속, 개인 선택 없는 원본 자동 보관, 관리자 정책 안내, 작은 화면, 기본 경로의 모델 미로딩을 로컬 Drive로 확인한다.

`node --test tests/camera-default-event.test.js`: 설정 재시작 복원, 기존 폴더·권한·부모 검증, 폴더 생성 없음, 관리자 전용 쓰기·다른 출처 거절을 확인한다.

`npm run test:camera-drafts`: 폰 크기 320/390px에서 대기 안내 직접 진입, 접힌 정보와 독립적인 개별 삭제, 전체 삭제 확인/취소, 삭제 후 즉시 안내 갱신과 재접속 일치, 접수 불확실 사진의 정리 확인, 원본 전송 대기·별도 오류 안내 유지를 확인한다.

기존 `test:camera-ui`는 새 메뉴·선택창을 실제 UI로 열도록 시나리오를 갱신했다. `scripts/helpers/camera-ui.cjs`는 앱 내부 상태를 바꾸지 않고 공통 화면 이동만 담당한다. 뽀샤시·꾸미기·AI·통신·대량 보관·영상·재시작·Drive 장애 회귀를 유지한다. 실제 스마트폰 카메라 권한과 기기별 성능은 실기기 확인이 필요하다.
