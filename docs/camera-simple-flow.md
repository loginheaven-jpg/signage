# 예봄 카메라 간편 촬영 흐름

## 기본 경로

첫 화면은 큰 `촬영하기`와 `사진 선택`이다. 폰 기본 카메라를 사용하며 첫 화면에서 카메라를 계속 켜거나 얼굴 모델을 미리 올리지 않는다. 기본 등록 방식은 화면에 올리기+원본 보관이다. 새 작업 때 목적 선택과 설정 시작 단계를 생략한다.

촬영·선택 → 사진 확인 → 화면에 올리기. 촬영 후 꾸미기를 자동으로 열지 않는다. 사진 확인에서 `사진 꾸미기`를 누른 경우에만 기존 뽀샤시·색감·프레임·꾸미기·AI를 연다. 적용 후 확인 화면으로 돌아오고 최종 등록 버튼을 눌러야 업로드한다.

첫 등록 때 등록자 이름·모니터가 빠졌으면 필요한 정보만 확인하고 기억한다. 그 창을 닫으면 전송하지 않는다. 이름은 입력한 표시 정보이며 인증은 기존 촬영 암호와 기기 소유자 쿠키를 유지한다. 여러 모니터가 있으면 임의로 하나를 고르지 않고 최초 선택을 요구한다. 모니터가 하나인 경우에도 상단에 선택 대상을 표시한다. 오프라인·목록 조회 실패를 연결됨으로 표시하거나 다른 모니터로 바꾸지 않는다.

사진 한 장은 큰 미리보기로 보여준다. 날짜·파일 정보는 펼침 영역, 문구·이메일은 `추가 옵션`으로 옮긴다. 영상 촬영, 보관만 하기, 내 사진은 보조 경로로 제공한다. `더보기`에서 등록 방식·이름·모니터·행사·사진 보내기·내 사진·설치·로그아웃을 연다. 기존 대량 보관·영상·메일·공유·취소 기능은 유지한다.

등록 후 `다음 사진 촬영`을 주 동작으로 제공하고, 공유와 등록 상태는 선택해서 연다. 서버 접수 완료와 실제 모니터 표시 확인은 구분한다. 표시 확인은 플레이어의 응답이 있을 때만 보여준다. 일부 전송 실패는 대기 사진을 남기고 같은 요청으로 재시도한다.

재접속·촬영 화면 이동 시 대기 사진을 버리지 않는다. 촬영 화면에서 `대기 사진 확인`으로 복귀한다. 실패 후 고정된 전송 설정은 목적·행사·이메일 변경을 막아 재시도 중 중복 전송을 방지한다. 브라우저 뒤로가기는 선택창 닫기와 이전 화면으로 이동하며, 접수 중에는 기존 이탈 방지를 유지한다.

## 행사 선택

1. 이 폰에서 최근 확정한 행사(`camera.lastTarget`)
2. 관리자 공통 현재 행사
3. 둘 다 없으면 미지정: 모니터 등록을 먼저 하고 원본은 비공개 보관 대기

행사명과 보낼 모니터는 첫 화면과 확인 화면 상단에 항상 보인다. 공통 행사에는 `공통`을 표시한다. 상속만 받은 공통 행사는 개인 선택으로 저장하지 않으므로 관리자가 다음 행사로 변경하면 새 작업에 따라간다. 선택 사진이 있거나 전송이 고정되었으면 기존 위치를 유지한다. 이미 위치가 지정된 사진·원본은 관리자 공통 행사 변경으로 이동하지 않는다.

개인 행사 선택은 `보관할 행사`에서 확인·저장해야 다음 사진의 기본 위치가 된다. 후보 폴더를 누른 뒤 창을 닫은 것만으로는 다음 사진 위치를 바꾸지 않는다. 저장할 때 현재 위치 미지정인 본인 사진 ID를 스냅샷으로 정해 적용한다. 이미 행사가 정해진 사진에는 재적용하지 않는다.

행사 미지정 등록 후에는 `원본 N장 · 보관할 행사를 선택해 주세요`를 표시한다. 원본 접수 전의 폰 종료 안내, 원본 전송 재시도, 위치 지정 대기 목록은 내 사진·등록 상태에서 확인한다. 폴더 조회 실패나 이동·삭제를 단순한 미선택으로 처리하지 않는다. 보관함 경계와 실제 쓰기 권한 검증은 기존 서버 경로를 유지한다.

## 관리자 공통 현재 행사

관리 화면 `라이브 송출 → 카메라 공통 현재 행사`에서 기존 연도·행사를 골라 지정하거나 해제한다. 설정만으로 폴더를 만들거나 사진을 이동하지 않는다. 연도·행사 폴더의 부모와 쓰기 권한을 검증한 뒤 저장하고, 검증 실패 시 이전 설정을 유지한다.

- 저장: `DATA_DIR/photo-archive/camera-default-event.json` (기존 영구 볼륨)
- 관리자: `GET/PUT /api/camera/default-event`, `GET /api/camera/event-folders`. `/api` 관리자 인증·동일 출처 검사를 상속한다.
- 촬영자: 기존 `/live/api/camera/config`의 `currentEvent`로 보관 대상 정보만 받는다. 관리자 인증값·Google 토큰은 받지 않는다.
- 공통 설정 해제 시 각 폰의 개인 선택과 진행 중 사진은 유지한다.

## 검증

`npm run test:camera-flow`: 실제 촬영 버튼→폰 파일 선택 경계→선택적 꾸미기→첫 등록 정보→반복 등록, 접수/표시 구분, 개인 우선/공통 대체, 확인 중 행사 유지, 재접속, 행사 없는 원본 대기/위치 지정, 관리자 패널, 작은 화면, 기본 경로의 모델 미로딩을 로컬 Drive로 확인한다.

`node --test tests/camera-default-event.test.js`: 설정 재시작 복원, 기존 폴더·권한·부모 검증, 폴더 생성 없음, 관리자 전용 쓰기·다른 출처 거절을 확인한다.

기존 `test:camera-ui`는 새 메뉴·선택창을 실제 UI로 열도록 시나리오를 갱신했다. `scripts/helpers/camera-ui.cjs`는 앱 내부 상태를 바꾸지 않고 공통 화면 이동만 담당한다. 뽀샤시·꾸미기·AI·통신·대량 보관·영상·재시작·Drive 장애 회귀를 유지한다. 실제 스마트폰 카메라 권한과 기기별 성능은 실기기 확인이 필요하다.
