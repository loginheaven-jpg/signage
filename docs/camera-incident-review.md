사진 취소는 새 카메라 화면과 API에도 남아 있다. 설정된 취소 시간(기본 60초) 안에

기존 기능의 소실이 아니다. 취소 시간이 지난 게시물의 사용자 철회도 현재 제공하지 않는다.
모니터가 연결 끊김 상태이면 현재 화면에서 즉시 지워졌다는 보장은 할 수 없다.
서버에서는 제거되므로 재접속 시 취소 사진을 새로 재전송하지 않는다.

## 폴더 조회의 확인된 결함과 원인 한계

기존 클라이언트는 폴더 요청을 15초에 중단했다. 서버는 매번 루트 메타데이터(개별
60초 제한), 루트 연도 목록(개별 30초), 연도 확인을 위한 중복 목록 또는 메타데이터,
행사 목록을 순서대로 조회했다. 종합 제한·캐시·앱 시작 사전 조회가 없었다.
최근 연도 ID가 있으면 인증/속도 오류까지 ID 이동으로 취급해 자동 재조회하여
화면의 확인 중 상태가 다시 시작됐다. 이 구조에서는 정상적이지만 느린 Drive도 실패한다.

운영 camera.js의 HTTPS 200 응답과 최신 복원 코드/요청 제한을 확인했다.
서비스 워커는 오프라인 안내 페이지만 캐시하며 camera.js/인증 API/사진을 캐시하지 않는다.
인증된 브라우저는 도구에서 제공되지 않았고, Railway CLI는 프로젝트 미연결 및
로그인 만료(Unauthorized) 상태여서 운영 폴더 요청·서버 로그는 확보하지 못했다.
따라서 이번 운영 증상이 Drive 지연인지 OAuth 만료/권한 부족인지는 아직 미확정이다.
과거 drive.file 범위 또는 잘못된 루트로 저장된 OAuth 연결이면 관리자 재연결이 필요하다.
이 경우 사전 조회와 캐시만으로 권한 문제가 해결되지는 않는다.

## 적용한 대책

- 앱 실행 시 최근 연도/폴더 사전 조회. 설정 화면과 동일 요청을 공유.
- 성공 목록 클라이언트 30초/서버 60초 재사용. 최대 5분 된 목록은 확인 시각을 표시하고 백그라운드 갱신.
- 수동 새로 확인은 캐시 우회. 실패한 목록은 빈 목록으로 저장하거나 신규 폴더 생성 근거로 사용하지 않음.
- 연도 중복 조회 제거. 서버 합계 20초 제한/Google 요청 중단, 화면 25초 제한/경과 시간/명시적 오류와 재시도.
- 자동 ID 복구 재조회는 실제 폴더 이동/삭제인 409 응답에만 적용.
- 실패 단계·상태/원인 코드·소요 시간의 민감정보 없는 운영 로그 추가.
- 기존 취소 버튼의 제목을 게시 취소/게시·보관 취소/보관 취소로 명확히 구분.

읽기 캐시는 목록 탐색에만 사용한다. 사진을 보관하거나 새 폴더를 만들 때는 기존의
실시간 부모 경로·권한·중복 폴더 검증을 유지한다. 오래된 ID로 교회 루트 밖에 쓰지 않는다.

## 검증

새 카메라 API에서 실제 HTTP 서버/WS 플레이어 연결로 게시 취소 → 제거 신호 →
공개 파일 404 → 재접속 미재전송을 확인한다. 실제 Chromium 웹 플레이어에서는
hero/grid 제거와 사진 다운로드 중 취소를 확인한다. 설치형 플레이어는 경로 비교와
공유 delivery gate 테스트로 확인했으며 운영 설치 기기 자체를 조작하지 않았다.

지연 Drive 대역으로 16초 조회를 재현하여 앱 시작 조회와 설정 요청이 한 번으로 합쳐지고
기존 15초 제한을 넘어 정상 완료되는지 확인한다. 합계 제한·늦은 응답·동시 요청·캐시 갱신·
권한 오류·삭제된 ID·쓰기 검증은 별도 자동 테스트로 확인한다.
폴더 시간 초과 UI에서 다시 확인 버튼이 활성화되고 확인 중 상태를 벗어나는 것도 검사한다.

운영 장애의 최종 원인 확정에는 인증된 폴더 API의 오류 응답 또는 Railway의
`[camera-folders]` 로그가 필요하다. 관리자 재연결이 필요하다는 응답이면 사진 보관 계정의
drive 권한과 지정 루트 편집 권한을 다시 연결해야 한다.
