# 교회 공용 보관 계정 연결 (2026-10-06)

촬영자마다 Google 계정을 연결하는 방식이 아니다. 교회 관리자가 지정 루트
`1sOi_69AEMwqoMbIyQ-vvZ2dpW7SD-Yfd`에 접근 가능한 보관 계정을 서버에 연결하면,
모든 촬영자는 기존 촬영용 접속만으로 폴더를 선택하고 사진을 올린다.
Google access/refresh token은 촬영자 브라우저에 전달하지 않는다.

## 장애 원인

사진 전용 `drive.file` 권한과 예전 보관 루트에서 연도·행사 폴더 및 교회사진 루트로
확장하면서 기존 `photo-archive/google-oauth.json`의 scope/root가 새 값과 다르면
서버가 연결을 거부했다. 사용자 캡처의 문구는 이 비교가 실패하는 분기와 정확히 일치한다.
관리자 연결 전환이 끝나지 않은 상태에서 카메라 사용자에게 관리자 안내까지 전달했다.
무한 확인 표시 수정과 실제 서버 계정 연결 복구는 별개다.

## 변경

- 이전 저장 메타데이터가 다르면 refresh token의 **실제** 승인 권한을 확인한다.
  이미 전체 Drive 권한이 있는 경우 지정 교회 루트의 편집 가능 여부를 확인한 후
  같은 서버 계정을 재사용하고 바인딩을 갱신한다. 검증 실패 시 기존 연결 파일을 보존한다.
- `drive.file`만 승인된 토큰을 코드를 바꿔 전체 권한으로 간주하지 않는다.
  이 경우 교회 보관 계정 소유자(관리자)가 **한 번** 추가 동의해야 한다.
- 전체 Drive 권한과 그 하위 Drive 권한이 함께 반환되는 정상 동의도 허용한다.
  누락된 전체 권한이나 사진 보관과 무관한 권한은 허용하지 않는다.
- 관리자 기본 연결은 Google 동의 후 지정 루트를 자동 검증·저장한다.
  이미 고정된 루트를 다시 Google Picker로 선택할 필요가 없다.
  기존 Picker 흐름은 관리자 `oauth/start?picker=1`에서 유지한다.
- 관리자 사진 보관함의 버튼은 ‘교회 보관 계정 연결 · 관리자 전용’으로 표시한다.
  Picker 설정이 없어도 고정 루트의 관리자 연결은 진행할 수 있다.
- 촬영 화면의 폴더·설정·보관 오류는 관리자 점검 안내로 바꾼다.
  촬영자에게 Google 연결/루트 선택을 지시하지 않는다. 모니터 표출과 개인 원본 대기는 유지한다.
- 관리자 OAuth의 브라우저 바인딩, 만료·1회 소비, 관리자 인증과 지정 루트 검증은 유지한다.

## 관리자 조치와 검증 한계

관리자는 `https://signage.yebom.org/photos`에 관리자 계정으로 접속해
‘교회 보관 계정 연결 · 관리자 전용’을 누르고 교회 보관 계정으로 권한을 승인한다.
지정 루트 검증까지 성공하면 공용 서버 연결이 저장되어 이후 촬영자에게 동일하게 적용된다.
정상 연결의 access token 갱신은 서버가 수행한다. 계정에서 동의를 철회하거나 토큰이
만료·취소된 경우의 관리자 재승인은 별개다.

자동 복구, 접근 불가 시 기존 연결 보존, 관리자 기본 동의 완료 및 Picker 호환,
서로 다른 촬영자들의 공용 목록 조회, 촬영자용 오류 분리를 로컬 대역으로 검증했다.
관련 테스트 61개 중 첫 통합 실행의 1개는 Windows 임의 테스트 포트가 fetch 금지 포트에
배정되어 실패했으며, 해당 camera-service 14개를 별도 재실행해 모두 통과했다.
Chromium 화면 검증 4종도 통과했다. 관리자 화면의 연결 버튼과 촬영자 화면의 공용 연결
안내를 직접 확인했으며, Google 401도 촬영자 로그인으로 이동시키지 않도록 검증했다.
운영 계정의 Google 동의는 계정 소유자의 대화형 승인이다. 인증된 운영 브라우저와
Railway CLI 권한이 제공되지 않아 실제 저장 토큰의 권한과 운영 Google 동의 완료를
대신 검증했다고 주장하지 않는다.
