# 모니터 표출 우선 개발 (2026-10-06)

## 사용자 흐름

보관하고 표출은 이름·모니터만 지정해 시작한다. 촬영/사진 선택 후 검토하고 게시하면
기기에서 긴 변 2048px 이하 JPEG를 먼저 보내 모니터에 전달한다. Drive 폴더 조회가
느리거나 실패해도 게시 시작과 다음 촬영을 막지 않는다. 최근 확정 보관 위치가 있으면
이를 사용하고, 없으면 게시 후 보관 영역에서 폴더를 정한다. 보관 전용은 기존 폴더 선지정을 유지한다.

원본은 뒤에서 그대로 전송한다. 새 게시 시 진행 중 원본 HTTP 요청을 중단해 게시를
우선하고, 게시 후 미접수 원본을 다시 전송한다. 원본이 접수되지 않은 동안 앱 닫기 경고와
대기 목록을 표시하며 IndexedDB로 재시작 복원한다. HTTP 원본 전송은 파일 단위 재시도이며
바이트 구간별 이어받기는 아니다. 원본 접수 뒤 Google 전송은 서버에서 진행한다.

위치 미지정 원본은 비공개 서버의 awaiting_target 상태로 유지하며 루트에 임의 저장하지 않는다.
위치 지정 버튼은 그 시점의 미지정 접수 ID 목록을 고정해 함께 적용하고, 다음 사진의
기본 위치도 확정한다. 기존 위치가 있는 사진은 일괄 변경하지 않는다. 폴더 선택창에서
다른 항목을 눌렀더라도 적용 버튼을 누르기 전에는 다음 사진의 확정 위치를 바꾸지 않는다.

게시만 취소는 개별/마지막 묶음으로 제공하며, 전체 취소 시간과 독립적으로 본인 사진만
철회한다. Drive 원본과 대기 메일은 유지한다. 메일만 취소와 전체 취소도 기존대로 제공한다.
철회 후 표출 재시도와 재접속 재전송으로 사진이 다시 나타나지 않는다.

## 상태와 처리 경계

| 작업 | API | 저장 상태/검증 |
| --- | --- | --- |
| 선표출 | POST preview | owner 서명 쿠키/출처 검사, 요청 ID와 사진·설정 hash, Google 호출 없음 |
| 원본 접수 | POST uploads/:id/original | both의 소유자만, 원본 hash/중복 검사, 비공개 원본 그대로 복사 |
| 폴더 후지정 | POST uploads/:id/target | 첫 지정은 서버 영수증에 먼저 기록하고 worker 대상으로 전환 |
| 게시만 취소 | DELETE uploads/:id/withdraw | live=withdrawn 기록 → 실제 WS 제거, 원본/메일 유지 |

보관 상태는 awaiting_original → awaiting_target 또는 pending → saved로 구분한다.
모니터 상태는 전달 요청과 실제 player displayed 응답을 분리한다. 표출 변환 실패 때도
both의 원본 접수는 계속 가능하다. 기기에서 축소할 수 없는 HEIC 등의 형식은 서버 변환을
위해 원본을 보내는 대체 경로여서 빠른 표출 효과가 제한된다. 서버에서도 변환하지 못하면
표출 오류로 표시하며 원본 보관 경로를 유지한다.

예전 /photo API와 이미 고정된 전송 대기 사진은 기존 경로로 호환한다.
전송 응답 유실은 같은 ID로 확인하며 자동으로 다시 게시하거나 메일을 중복 예약하지 않는다.
원본 hash와 위치 미지정 상태는 서버 재시작 후 복원된다. 위치 영수증과 원본 기록 사이의
재시작도 mount 시 복구한다. 실제 보관/폴더 생성은 기존 부모·권한 검증과 생성 journal을 유지한다.

## 검증 결과와 한계

로컬 Chromium에서 약 15MB 원본과 폴더 조회를 보류한 상태로 작은 JPEG를 선게시하고,
원본 요청 중 새 게시/앱 재시작을 거쳐 두 원본을 뒤늦게 같은 행사로 저장했다.
표출 전송 약 22KB, 로컬 첫 게시 요청 약 1.1초를 확인했으나 운영 모니터의 실제 표출 시간
측정값은 아니다. 원본 바이트 비교, 게시만 취소 후 보관 유지, 묶음 철회도 확인한다.

실제 서버 HTTP/WS에서는 preview → 모니터 displayed 응답 → 원본 접수 → withdraw →
파일 404/WS 제거 → 보관 원본 접근 유지 → 재접속 미재생을 확인한다.
기존 이메일/공유/메일만 취소/전체 취소/홈·뒤로가기/폴더 선택/권한 회귀도 검증한다.
운영 Google 계정과 실제 휴대폰/Kakao 수신자, 운영 모니터에는 테스트 사진이나 메일을 보내지 않는다.
