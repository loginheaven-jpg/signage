# 위치 미지정 원본의 관리자 일괄 배정

## 원인과 새 기본 정책

기존 빠른 촬영 경로는 `target` 없는 미리보기를 허용하고, 원본을 `awaiting_target`으로 접수했다. 공통 행사는 서버가 아니라 촬영 화면의 설정 조회·요청 구성에 의존했다. 공통 행사가 미설정이거나 촬영 화면이 대상 없이 요청하면 서버는 기본 위치를 보충하지 않았으며, Drive 작업자는 이 상태를 처리하지 않았다. 이는 코드에서 확인한 경로이며 특정 운영 95건의 정확한 접수 원인은 운영 영수증·설정·배포 버전 확인이 필요하다.

이제 빠른 사진·일반 사진·영상 모두 개인의 명시적인 행사 선택이 없으면 서버가 `교회사진 루트 / 촬영 연도 / 미분류`를 확정한다. 연도와 미분류 폴더는 Drive 전송 작업 중 없을 때 생성한다. 촬영일은 기존 날짜 추출 규칙(명시한 날짜, EXIF, 파일 수정일)을 사용하고 알 수 없으면 접수일을 사용한다. 연도 경계는 한국 시간이다. 확정된 연도는 재시도 시 현재 연도로 바뀌지 않는다. 같은 이름의 폴더가 여러 개면 임의로 고르지 않고 오류와 원본을 보존한다.

촬영 화면은 자동 기본값을 개인 선택으로 기억하지 않는다. `targetSource=common/automatic`이거나 대상이 없는 요청에도 서버가 같은 정책을 적용한다. 이전 공통 행사 설정 파일은 보존하지만 새 촬영 기본값에는 사용하지 않는다. 개인이 선택한 폴더 오류를 미분류로 조용히 덮어쓰지는 않는다. 보관 없는 표출(`live`)도 그대로 보관하지 않는다.

기존 `awaiting_target` 사진을 이 정책으로 자동 소급 이동하지 않는다. 관리자가 원본을 확인한 뒤 별도로 배정한다.

## 관리자 사용 순서

1. 새 코드가 배포된 서버의 **사진 보관함**에 관리자 로그인한다.
2. **위치 미지정 전체 선택**으로 페이지를 넘는 대상까지 선택한다(최대 500개). 개별 선택 또는 페이지 선택도 가능하다.
3. **선택 사진 행사 배정**을 누르고 기존 행사 폴더를 선택하거나 Drive 폴더 링크를 입력한다.
4. **원본·저장 위치 확인**으로 대상 경로·가능 개수·실패 목록을 확인한다. 이 단계는 배정하거나 폴더를 생성하지 않는다.
5. **확인한 사진 배정**으로 원본 확인에 통과한 항목만 배정한다. 배정 접수는 Drive 완료와 다르다. 같은 요청을 재시도해도 다른 위치로 바꾸거나 중복 업로드하지 않는다.
6. 목록에서 **드라이브 보관 완료**를 확인한다. 읽기·권한·전송 오류가 난 원본은 그대로 유지된다.

## 요청된 95건의 운영 작업

지정 행사 폴더 ID: `1RanF1J2eiK0um3TqF-id-mUja0ps160J`.

먼저 운영 `DATA_DIR`와 볼륨 마운트를 확인하고, 원본과 메타데이터를 별도 저장소에 백업한다. 위 UI에 해당 폴더 링크를 입력하면 서버가 실제 Drive 폴더 이름, 연도 폴더, 교회사진 루트와의 관계 및 쓰기 권한을 검증한다. 폴더 이름을 추측해 새 행사 폴더를 만들지 않는다.

선택 건수가 95인지, 원본 확인 통과 건수와 실패 건수의 합이 95인지 확인한다. 누락·손상 건은 별도 목록으로 남기며 복구 완료로 계산하지 않는다. 다른 행사 사진이 섞여 있으면 선택에서 제외한다. 95건의 Drive 완료·무결성 확인 전후 기록을 대조한다. 이 문서는 운영 서버의 95건이 이미 검증·이관되었다는 뜻이 아니다.

## 원본 보호와 검증

- 배정 전 파일 존재·0바이트 여부·기존 SHA-256 일치 여부를 확인한다. 이미지는 디코더가 끝까지 읽을 수 있는지도 검사한다.
- `DATA_DIR/photo-archive/assignment-backups/<photo-id>/`에 원본 사본과 `before.json`을 남기고 사본의 SHA-256을 대조한 뒤 배정 기록을 저장한다. 이 사본도 같은 볼륨에 있으므로 별도 외부 백업을 대체하지 않는다.
- 복구 대상의 원래 서버 원본과 복구용 사본은 Drive 보관 완료 후에도 자동 삭제하지 않는다. 운영 확인 후 별도 보존 정책으로 정리한다.
- Drive 전송은 저장한 동일 파일 ID로 재시도한다. Drive의 대상 부모·앱 사진 ID·파일 크기·MD5가 일치해야 `saved`와 `verifiedAt`을 기록한다. 미확인·불일치 시 원본을 유지한다.
- 배정 API는 기존 `/api` 관리자 인증과 동일 출처 검사를 상속한다. 촬영자 권한으로 다른 사람 사진을 배정할 수 없다.
- `POST /api/photos/assign/preview`, `POST /api/photos/assign`: `{ "ids": ["photo-id"], "folderId": "existing-event-folder-id" }`. 각 항목의 결과를 반환한다. Drive 완료는 보관함 상태에서 별도 확인한다.

## 검증 명령

호스트 의존성을 설치한 뒤 저장소 루트에서:

```sh
node --test tests/photo-assignment.test.js tests/camera-service.test.js tests/camera-video.test.js tests/photo-archive.test.js
node scripts/smoke-photo-assignment.cjs
node scripts/smoke-camera-flow.cjs
```

브라우저 스모크 검사는 Playwright Chromium이 필요하다. 클라우드 온보딩 환경에서는 시스템 Chromium을 사용하는 기존 보조 설정을 적용할 수 있다.
