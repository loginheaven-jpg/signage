# 폴더 확인 무한 대기 재점검 (2026-10-06)

## 재현한 원인

최근 선택 폴더가 없는 새 기기에서 최초 폴더 조회가 실패하면 `renderEvents`의
`recent?.yearId === dataset.selected` 비교에서 양쪽 값이 모두 undefined가 되어 참이 된다.
이어 `recent.eventId`를 읽으며 null 참조 오류가 발생한다. 오류 안내를 만드는 과정에서
다시 오류가 발생하므로 폴더 상태에 ‘확인 중’만 남고 재시도도 제대로 동작하지 않는다.
사진 표출은 별도 경로이므로 정상 완료될 수 있다. Chromium에서 같은 증상을 재현했다.

서버에서도 시간 초과된 폴더 요청을 원래 Google 요청이 끝날 때까지 pending에 유지했다.
Google 인증/읽기 요청이 끝나지 않으면 후속 재시도가 이미 실패한 Promise를 계속 공유한다.
Drive API에 전달한 timeout/AbortSignal은 별도 OAuth 인증 토큰 갱신 요청에 전파되지 않는다.

## 변경

- 최근 연도 ID가 실제로 있을 때만 최근 폴더를 비교한다. 오류 안내를 목록 정리 전에 표시한다.
- 브라우저는 fetch와 응답 본문 읽기 전체를 별도 Promise deadline으로 제한한다.
  중단 신호를 무시하는 전송도 25초에 UI를 종료하며, 늦게 오는 결과는 목록에 적용하지 않는다.
- 서버는 20초 종합 제한이 끝나면 실패 요청을 pending에서 해제한다. 과거 요청의 늦은 완료는
  새 요청을 삭제하거나 캐시를 덮어쓰지 않으며, 추가 행사 조회도 시작하지 않는다.
- OAuth 인증 전송에도 10초 제한과 자동 인증 재시도 0회를 적용한다. 보관 작업 자체의
  기존 서버 재시도 정책은 유지한다.
- 폴더 오류에 ROOT/YEARS/EVENTS 단계와 상태 코드를 고정 문자열로 표시한다.
  계정·토큰·Google 요청 전문은 응답이나 로그에 노출하지 않는다.
- 조회 실패는 빈 목록/폴더 없음으로 취급하지 않는다. 목록 조회가 성공하기 전에는
  새 폴더 생성 또는 보관 위치 확정을 허용하지 않고, 표출 촬영은 계속 가능하다.

## 검증 범위

최근 폴더 없는 기기의 최초 403/504, 응답 본문 무응답 및 AbortSignal 무시,
오류 후 재시도 성공, 오래된 응답 무시를 Chromium에서 검증했다.
Google 인증 대역 서버의 무응답 후 timeout/재시도 성공, 폴더 서버의 시간 초과 후
새 요청 처리와 늦은 요청 격리를 확인했다. 이메일·사진 공유·원본 전송·게시 취소도 회귀 검증했다.
관련 Node 테스트 56개와 Chromium 화면 검증 4종이 통과했다. agent-browser에서도
최근 폴더 없는 기기의 최초 조회 실패 → 오류 표시 → 다시 확인 → 목록 복구를 직접 확인했다.

운영 camera.js의 반영 여부는 공개 정적 응답으로 확인할 수 있다. 인증된 운영 브라우저가
제공되지 않았고 Railway CLI 인증도 만료되어, 이번 운영 Google 요청의 최초 실패가
권한/계정 만료/지연 중 무엇인지는 아직 확인하지 못했다. 화면 예외 수정과 계정 연결
문제의 해결은 구분한다. 목록이 여전히 읽히지 않으면 화면의 FOLDERS 단계/상태 코드로
계정 재연결 또는 네트워크 문제를 판단한다.
