# 예봄 카메라 확장 설계 (2026-10-06)

## 작업 흐름

`/camera`, `/m`, `/m.html`, `camera.yebom.org/`는 같은 카메라 화면이다.
촬영용 로그인 뒤 목적을 먼저 고른다. 홈 메뉴는 `보관하고 표출`(기본 강조), `보관없이 표출`, `교회폴더에 저장` 순서다. 기본 강조는 자동 진입이 아니며 사용자가 선택한다.
표출 목적은 업로더 이름·모니터만 지정해 작업을 시작한다. `보관하고 표출`의 폴더는 작업 화면에서 나중에 정할 수 있으며 최근 확정 위치가 있으면 그대로 사용한다. 보관 전용 목적은 행사 폴더 지정 후 시작한다.
목적 변경은 상위 화면, 설정 변경은 같은 목적의 행사·모니터·이름 변경이다.
홈에서는 세 메뉴와 마지막 작업의 `작업 이어가기`를 함께 보여준다. 재접속 때 자동 진입하지 않고 사용자가 선택한다. 진행 중인 작업은 연말에도 자동으로 바뀌지 않는다.
상단의 고정 `⌂ 홈` 버튼은 설정과 작업 화면에서 항상 보인다. 홈 이동 시 선택 사진·문구·확정 설정을 유지하고 대기 사진 수를 보여준다.
브라우저/휴대폰 뒤로가기는 선택창 닫기 → 이전 화면 → 홈 순으로 이동한다. 홈에서의 뒤로가기는 일반 브라우저 동작이다.
사진 접수 중에는 홈 버튼을 잠그고 브라우저 뒤로가기도 현재 화면으로 되돌린다. 실제 페이지 닫기는 브라우저 이탈 확인을 사용한다.
PC에서는 파일 선택 또는 연결 카메라의 브라우저 촬영, 휴대폰에서는 기본 촬영/앨범을 사용한다.
PC 촬영은 카메라 접근 허용 후 미리보기에서 촬영하며 닫기·페이지 이탈 때 카메라를 해제한다. 실제 카메라와 설치 동작은 기기별 검증이 필요하다.

사진 선택 뒤 미리보기·사진별 날짜 수정·제외·추가를 제공한다. 명시적으로 전송하기 전에는 업로드하지 않는다.
업로더와 목적·행사는 기억한다. 문구는 전송 후 비우되 계속 사용을 선택할 수 있다. 모니터 표출 목적에서 받는 이메일은 마지막 입력/사용 후 10분간 유지하며 이전 주소 안내·지우기·도메인 오타 교정 제안을 제공한다. 홈 이동/재접속만으로 유지 시간을 연장하지 않는다.
`보관하고 표출`과 `보관없이 표출`에서는 사진 선택 전 이메일 입력과 접수 후 카카오톡 등의 파일 공유를 제공한다. `교회폴더에 저장`에서는 메일·공유를 제공하지 않고 서버도 메일을 예약하지 않는다.
공유는 네이티브 공유창에서 사용자가 카카오톡·받는 사람을 선택하는 방식이다. 공유창이 없으면 사진별 내려받기를 제공한다. 실제 메시지 전송을 서버가 확인했다고 표시하지 않는다.
공유용 JPEG는 마지막 접수 묶음만 기기에 저장하고 페이지 재시작 시 복원한다. 일부 기기에서 변환 불가한 형식은 원본 파일로 공유/내려받는다. 사진 취소 시 해당 공유 사본도 제거한다.
메일은 이전처럼 취소 시간 이후 발송하며 새 빠른 표출 경로에서는 표출용 JPEG를 첨부한다. Drive 원본은 그대로 유지한다. 내 업로드와 마지막 묶음에서 게시만 취소, 메일만 취소, 사진 보관까지 취소를 구분한다. 게시만 취소는 보관/메일을 유지하며 본인 전체 취소 시간 이후에도 가능하다.
API 요청에는 원본/기존 전송 90초, 빠른 표출/일반 조회 15초, 폴더 조회 25초 시간 제한을 둔다. 시간 초과 시 대기 사진·고정 요청 ID를 유지해 중복 접수 없이 재시도한다.
선택한 원본과 전송 대기 설정은 브라우저 IndexedDB에 저장해 페이지 재시작 후 복원한다.
저장 공간 부족/비공개 모드에서 기기 저장이 실패하면 화면을 닫지 말라는 안내를 표시한다.
표출 실패는 사용자가 재시도한다. 원본 전송은 접수 후 및 앱 재시작/인터넷 복구 때 자동으로 이어가며 실패한 원본에는 명시적 재시도 버튼을 제공한다. 서비스 워커는 사진이나 API 응답을 캐시하지 않는다.

표출용 사진은 기기에서 긴 변 2048px 이하 JPEG로 만들고 원본보다 먼저 `/preview`로 보낸다.
서버는 Google 조회 없이 전달한다. 원본은 이후 `/uploads/:id/original`로 보내며 다음 사진 게시 때
진행 중 원본 요청을 중단하고 게시 뒤 재개한다. 중단 요청이 이미 접수됐어도 해시/접수 ID로 중복 보관을 막는다.
기기에서 디코딩할 수 없는 형식은 원본을 서버에 보내 변환하는 대체 경로이며 빠른 전송 효과가 제한된다.
표출 요청과 원본 전송은 별도 상태이며 서버 접수를 실제 모니터 표시 성공으로 표시하지 않는다.
원본 대기 목록도 IndexedDB에 보관한다. 서버 원본 접수 전에는 앱 닫기 경고를 표시하고,
접수 이후에는 서버 작업으로 Drive 보관을 이어가므로 앱을 계속 열어둘 필요가 없다.
폴더 미지정 원본은 `awaiting_target`으로 서버에 유지하며 TTL로 원본을 지우거나 루트에 임의 저장하지 않는다.

## Drive 폴더 규칙

- 루트: `1sOi_69AEMwqoMbIyQ-vvZ2dpW7SD-Yfd` (#교회사진영상).
- 서버 `GDRIVE_CAMERA_ROOT_ID`로만 변경할 수 있다. 기존 `GDRIVE_PHOTO_FOLDER_ID`와 순환 콘텐츠의 `GDRIVE_FOLDER_ID`를 새 카메라 루트로 재사용하지 않는다.
- 현재 한국 연도를 기본 선택하고 1900~2199 범위의 과거/신규 연도도 입력할 수 있다.
- 이 브라우저에서 최근 선택한 연도·행사 폴더를 기본 위치로 복원하며, 연도 변경 시 해당 연도의 최근 폴더를 복원한다. 표출 전용 작업을 거쳐도 마지막 보관 위치를 유지한다.
- 연도 아래 `저장 폴더 선택` 버튼으로 목록을 연다. 휴대폰에서는 하단 선택창이다. 맨 위 `＋ 새 폴더`, 행사명 검색, 기존 폴더 목록을 제공한다.
- 목록 정렬은 최근 선택 폴더 우선, 날짜 접두어(`YYYYMMDD`, `YYYY-MM-DD`, `YYYY.MM.DD`)가 있는 폴더의 행사 날짜 내림차순, 날짜 없는 폴더 이름순이다. 수정일은 정렬에 쓰지 않는다. 동일 이름은 ID를 함께 표시한다.
- 현재 저장 경로는 폴더 버튼과 작업 요약에 표시한다. 기억한 폴더가 없거나 권한이 없으면 자동 대체하지 않고 다시 선택하도록 안내한다. 조회 실패는 보관 전용 시작과 새 폴더 선택을 막으며 표출 시작/반복을 막지 않는다.
- 보관하고 표출에서 `이 위치로 보관 · 다음 사진에도 사용`을 누르면 그 시점에 위치 미지정인 본인 접수 ID들을 확정해 적용한다. 이미 위치를 지정한 이전 사진을 새 위치로 바꾸지 않는다. 다음 사진의 기본 위치를 함께 기억한다.
- 루트 바로 아래 정확히 네 자리 연도 이름을 찾는다. 연도불명 등 기존 특수 분류를 재배치하지 않는다.
- 해당 연도 바로 아래 폴더만 행사로 나열한다. 이미지·영상·바로가기는 제외한다.
- 신규 행사명은 NFC 정규화, 앞뒤 및 반복 공백 정리, 1~80자, 경로 구분자·제어문자 제외.
- 시작일은 선택 사항. 있으면 `YYYYMMDD 행사명`, 없으면 행사명만 사용한다. 날짜와 연도가 다르면 정정을 안내한다.
- 연도/행사는 첫 실제 사진 접수 이후 Drive 전송 때 생성한다. 설정·사진 선택 취소만으로 빈 폴더를 만들지 않는다.
- 정확히 같은 이름은 기존 폴더 사용, 비슷한 이름은 기존 목록에서 직접 선택. 중복된 이름은 폴더 ID로 명시 선택.
- 조회 실패를 폴더 부재로 판단하지 않는다. 저장 시 선택한 연도/행사 ID의 부모와 삭제 여부를 다시 검증한다.
- 자동 생성은 서버에서 직렬 처리하고, 생성 전 발급한 Drive ID를 `folder-journal.json`에 기록한다.
  응답 유실/재시작 후 같은 ID로 재시도한다. 이전 생성 폴더가 이동/삭제됐으면 새 폴더를 임의 생성하지 않는다.
- 하나의 영구 DATA_DIR에는 하나의 서버 쓰기 프로세스를 사용한다. 다중 replica 운용 전에는 DB 분산 잠금으로 전환해야 한다.

## 사진과 파일명

- 실제 파일 서명을 검사하며 JPEG/PNG/GIF/WebP/HEIC/HEIF/AVIF/TIFF를 허용한다. SVG/실행파일은 제외한다.
- 한 장당 50MB, UI 한 번에 30장. 원본은 변환 없이 비공개 보관 대기열에 저장한다.
- 새 표출용 복사본은 기기에서 긴 변 최대 2048px, JPEG 82%, 방향 보정, 확대 없음으로 변환한다. 서버는 최대 2560px JPEG로 검사/변환한다. 이전 API와 표출 재시도는 기존 3840px 변환을 유지한다.
  디코더가 지원하지 않는 HEIC 등은 원본 보관과 표출 오류를 각각 표시한다.
- 파일명: `사진날짜YYYYMMDD-HHMMSS_업로더이름_접수일시YYYYMMDD-HHMMSS.ext`.
- 사진 날짜: 사용자 수정값 우선, 그 외 EXIF 촬영일/생성일, 없으면 파일 수정일시, 모두 없으면 `날짜미상`.
  시간대 없는 EXIF와 날짜 수정 입력은 한국 시간으로 해석한다. 날짜 출처·원본명도 메타데이터에 보관한다.
- 접수일시는 서버 최초 접수 시각으로 고정한다. 이름 충돌에는 `_02`, `_03` 번호를 붙인다.
- 실제 Drive 저장을 확인한 뒤 서버 보관용 복사본을 정리한다. 모니터 임시파일 TTL과 원본 보관은 독립적이다.
- 기존 로컬 보관 기록과 Drive 파일은 유지한다. 이전 루트의 기존 로컬 기록도 조회/재전송/삭제 대상으로 남는다.

## API·인증·결과

모니터 선택도 휴대폰 하단 선택창을 사용한다. 연결된 모니터를 먼저 표시하고 초록색 원+`연결됨`, 회색 원+`연결 끊김`을 함께 표시한다.
이 상태는 승인된 플레이어의 서비스 연결 상태이며 실제 모니터 전원 상태가 아니다. 선택창을 열 때 최신 설정 API를 조회하고, 작업 요약에서도 연결 상태를 갱신한다.
모니터 목록 확인 실패 시 오류를 표시하고 설정 확정을 막는다. 연결이 끊긴 모니터는 사용자가 선택할 수 있으며 실제 표시 결과는 업로드 이력에서 따로 확인한다.

카메라 API는 `/live/api/camera/*`이며 촬영 역할 인증과 동일 출처 검사를 거친다.
카메라 사용자에게 관리자 API·Google 토큰을 제공하지 않는다.
서버가 서명한 HttpOnly `camera_owner` 쿠키로 기기별 업로드 조회·취소를 제한한다. 입력한 이름을 인증에 사용하지 않는다.
사이트 데이터를 지우거나 다른 브라우저에서 열면 이전 기기의 내 업로드 이력을 볼 수 없다. 관리자 보관함에는 남는다.

- `GET config`: 목적별 접수 상태, 한국 연도, 모니터 연결 상태, 제한.
- `GET folders?year=&yearId=&refresh=1`: 기존 연도/행사. 조회로 폴더를 생성하지 않는다. refresh=1은 새 조회.
- `POST photo`: multipart 원본 + 목적/행사/등록자/날짜/전송요청 ID.
- `POST preview`: 작은 표출용 사진 + 표출 목적/모니터/메타데이터. both의 행사 지정은 선택. Google를 기다리지 않는다.
- `POST uploads/:id/original`: both의 비공개 원본 접수. 원본 해시로 재시도/변경 충돌 검사, 최초 접수 시각 유지.
- `GET uploads`: 기기별 최근 60건. 서버 접수/Drive 보관/모니터 전달/실제 표시 결과 분리.
- `POST uploads/:id/retry`: 해당 기기의 Drive 전송 재시도.
- `POST uploads/:id/display`: 실패/처리 미확인 사진의 모니터 전송만 사용자가 재시도. Drive에 다시 저장하지 않는다.
- `POST uploads/:id/target`: 폴더 오류로 Drive 파일 ID를 아직 발급하지 못한 사진을 본인이 새로 선택한 행사에 저장.
- `DELETE uploads/:id`: 설정된 취소 시간 안의 본인 취소. Drive는 휴지통 이동, 모니터 제거, 대기 메일 취소.
- `DELETE uploads/:id/mail`: 기기 소유자만 발송 시작 전 메일을 따로 취소. 사진 보관·표출은 유지.
- `DELETE uploads/:id/withdraw`: 본인 모니터 게시만 취소. 원본 보관/대기 메일 유지, 전체 취소 시간과 독립, 반복 요청 가능. 철회한 사진의 재표출은 거부.

사진별 요청 ID와 기기 소유자로 접수 ID를 결정하고 원본+설정 fingerprint를 비교한다.
동일 요청의 응답 유실 재시도는 기존 결과를 반환하며 다시 보관·표출하지 않는다.
전송을 시도한 대기 사진은 설정을 고정한다. 응답이 불확실한 상태에서 목적·날짜를 바꿔 중복을 만드는 것을 막는다.
Drive가 끊겨도 이미 지정한 행사에 대한 서버 접수와 원본 대기를 유지한다. 새 행사 선택은 조회가 성공해야 가능하다.
모니터 접수가 닫히거나 변환이 실패해도 둘 다 목적의 원본 보관은 유지한다.
모니터 전달 요청을 실제 표시 성공으로 표시하지 않는다. 플레이어의 `displayed` 수신으로만 표시 확인한다.
서버 재시작 중 표출 결과가 불확실하면 성공으로 추정하거나 자동으로 재송출하지 않는다.
모니터 전용 원본도 비공개 임시 영역에 보관하며 설정된 사진 TTL 이후 사용할 수 없다. 주기적으로 정리한다.

관리 `/api/live`의 `enabled`는 모니터 접수, `archiveEnabled`는 사진 보관 접수이다.
기존 설정 파일은 archiveEnabled=true로 이행한다. 보관 접수를 닫아도 기존 대기열 재시도와 기존 보관 사진은 유지한다.
기존 `/live/api/photo`와 플레이어 프로토콜은 호환성을 유지한다.

## Google 연결 및 배포

Node.js 22 이상, `pnpm install --frozen-lockfile`, 영구 볼륨 DATA_DIR/UPLOADS_DIR를 사용한다.
새 원본/기기서명키/전송접수 기록/폴더 journal은 DATA_DIR/photo-archive 아래에 있으며 공개 uploads와 분리한다.
카메라 접속 도메인의 HTTPS 인증서와 Railway Custom Domain을 확인한다.

기존 `drive.file`은 선택한 루트의 기존 자식 폴더 전체를 보장하지 않는다.
연도/행사 목록과 기존 행사에 대한 쓰기를 위해 관리자 OAuth를 **drive** 범위로 다시 연결한다.
이 권한은 Google 계정의 전체 Drive 조회·관리 권한이며, 루트 제한은 앱의 서버 검증으로 적용된다.
Google Cloud 동의 설정/앱 검증 요구를 확인하고 개인정보 안내에도 넓은 권한을 명시한다.
키/갱신토큰은 서버 비밀 변수·비공개 볼륨에만 둔다. 코드 push가 실제 Google 동의나 운영 재연결을 수행하지 않는다.
기존 저장 scope/루트가 다르면 실제 승인 권한과 지정 루트 편집 권한을 확인해 충분한 권한의
기존 서버 연결을 재사용한다. 추가 권한이 필요한 경우 관리자에게 한 번 재동의를 요청한다.
촬영자에게 Google 연결을 요구하지 않으며, Google의 실제 권한을 코드를 바꿔 넓히지 않는다.
OAuth callback은 기존 signage.yebom.org에서 수행하고 기본 관리자 동의는 지정 루트를
자동 검증·저장한다. 기존 Picker 흐름도 관리자 `oauth/start?picker=1`에서 지정 루트만 허용한다.
상세 전환 및 사용자/관리자 안내 구분은 [camera-shared-drive-connection.md](camera-shared-drive-connection.md)를 참고한다.

## 검증

`cd host; npm test`: 원본 바이트 보존, 목적별 접수, 중복 응답 재시도, 기기별 격리,
폴더 부모 검증·중복·조회 실패·생성 timeout/restart, 날짜, 기존 HTTP/WebSocket·메일/OAuth 회귀.
`cd host; pnpm exec playwright install chromium; npm run test:camera-ui`:
실제 Chromium에서 목적별 반복 작업, 원본 접수, 신규 폴더, 대기 사진 재시작 복원, 표시 결과, 모바일 폭 및 보관함·클립보드 검증.
`node scripts/camera-preview.cjs`는 localhost에서만 실행하는 가짜 Drive 기반 미리보기이다. 운영 서버로 사용하지 않는다.
실제 Google 계정의 폴더 생성·원본 저장·휴지통 이동은 운영 재연결 후 별도로 확인한다.

## 폴더 조회 대기 개선

앱 초기 config 응답 직후 최근 저장 연도/폴더(없으면 현재 한국 연도)를 백그라운드로 조회한다.
설정 화면은 동일한 진행 중 요청에 합류하며, 30초 이내의 클라이언트 성공 응답을 재사용한다.
서버는 성공한 목록을 60초 재사용하고, 최대 5분 전 목록은 확인 시각/갱신 안내와 함께
즉시 반환하며 백그라운드로 갱신한다. 서버 재시작 후 첫 조회는 캐시가 없는 정상 조회다.
인증/권한/폴더 삭제 오류가 확인되면 해당 캐시를 폐기한다. 목록 다시 확인은 캐시를 우회한다.

루트 확인·연도 목록·행사 목록의 합계에 서버 20초 제한과 Google 요청 AbortSignal을 적용한다.
클라이언트는 25초 안에 성공 또는 오류를 표시하고 경과 시간을 알려 준다.
실패를 폴더 부재로 취급하지 않으며, 폴더가 실제로 이동한 409 응답에만 최근 연도 ID를 버리고
한 번 재조회한다. 속도/인증 오류에 무조건 재조회하던 동작은 제거한다.
연도 목록을 다시 읽던 중복 호출도 제거했다. 저장/폴더 생성의 부모·권한 검증은 실시간으로 유지한다.
운영 로그 `[camera-folders]`에는 실패 단계(root/years/events), 고정 상태/원인 코드,
소요 시간만 남기며 사용자 이름/메일/Google 요청/토큰은 기록하지 않는다.
